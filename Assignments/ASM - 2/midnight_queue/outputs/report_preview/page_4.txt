F. The Mathematical Case
M1 — Insertion Sort. If I is the inversion count, every shift removes one inversion: moves = I+n−1, comparisons = I+n−1−z, with 0 ≤z ≤n−1.
Thus T(n, I) = Θ(n + I). Best: I = 0, Θ(n); random distinct keys: E[I] = n(n −1)/4, Θ(n2); reverse: I = n(n −1)/2, Θ(n2). C5 inversion counts
at the four sizes: 3,007; 325,988; 34,333,390; 272,954,546. Moving only 1% of records does not guarantee linear work.
M2 — Merge Sort. Iterating T(n) = 2T(n/2) + cn gives T(n) = 2jT(n/2j) + jcn. At j = log2 n, this is nT(1) + cn log2 n = Θ(n log n). Master’s
theorem: a = b = 2, f(n) = Θ(nlogb a) = Θ(n); case 2 confirms Θ(n log n).
M3 — Quick Sort. (a) Iteration of T(n) = T(n −1) + cn yields T(1) + c ∑n
j=2 j = Θ(n2). (b) The balanced recursion tree has log2 n levels of
Θ(n) work, hence Θ(n log n). (c) For T(n) = T(n/10) + T(9n/10) + n, each complete level conserves total size n. The first ⌊log10 n⌋levels give
Ω(n log n); depth is at most ⌈log10/9 n⌉, giving O(n log n). Together these prove the tight bound Θ(n log n).
M4 — Heap Sort. A height-h node costs O(h) to sift, and there are at most ⌈n/2h+1⌉such nodes. Bottom-up build costs O(n ∑
h≥0 h/2h+1) = O(n);
visiting the internal nodes gives Ω(n), so build is Θ(n). Each of n−1 extractions costs O(log n); total worst-case time is Θ(n log n), with O(1) auxiliary
space.
M5 — Top-K. For 2 ≤K ≤n, full sort and prefix costs Θ(n log n). For the heap, bottom-up build is O(K), scanning is O(n + A log K) for A
accepted replacements, and ordered publication is O(K log K); worst case O(n log K + K log K). The buffer costs O(K log K + n + A(K + log K)):
rejected records need one comparison, accepted records need binary search and explicit shifting. Worst case O(nK); for a random permutation of
distinct keys, record i > K enters with probability K/i, so E[A] = K(Hn −HK), where Hj is the j-th harmonic number. An idealised comparison
equates (n + K) log2 K = n log2 n; actual crossover depends on constants, arrival order and acceptance rate, and is not established beyond the
measured grid. The prediction that full sort overtakes near K=10,000 at n=100,000 was wrong on C2: heap 0.498 s, full sort 2.89 s. At full size and
K=n/10=28,480: heap 1.29 s, full sort 8.94 s. These are measured points, not a universal crossover.

H. Recommendation to the Platform Lead
1. Overnight batch: ship Merge Sort. Lowest worst completed time across C1–C5 at full size wins. Worst medians: Hardened Quick Sort: 31.13 s;
Heap Sort: 15.84 s; Merge Sort: 11.29 s. Hardened Quick Sort now has an in-place heap fallback after twice the binary-log depth, guaranteeing O(n
log n) worst-case time and O(log n) stack. The choice assumes the unknown next batch resembles the tested conditions; it is wrong for an already
ranked batch, where insertion sort takes 0.382 s.
2. Shift queue: ship Size-K Heap. Across the 28 measured cells it minimises worst slowdown relative to the winner: Bounded Insertion Buffer:
max regret 140.88x; Full Sort (Hardened Quick Sort): max regret 186.16x; Size-K Heap: max regret 1.12x. The recommendation assumes K is small
relative to n and scores do not change after arrival. It can be wrong near full capacity, or for a fixed small corner where another method is a few
milliseconds faster. Changing scores require an update/rebuild mechanism. The operational K=52 queue still contains no frauds; the half-capture
capacity must be considered separately.
3. Live refresh: ship maintained size-K heap. Algorithm-only totals: 60 min: rerank 2.84 min, heap 0.284 s, merge 6.36 s; 10 min: rerank DNF,
heap 0.538 s, merge 9.61 s. A maintained heap touches new records once and avoids re-ranking history. This assumes immutable scores and
windows large enough to amortise publication. Very small windows or K near n can favour window merge. The w≈n/K comparison is a rough guide,
not a measured universal crossover.
