B. Build the Contenders
The package src/midnight_queue/ contains Insertion Sort (in-place shifting), top-down stable Merge Sort, Naive Quick Sort (last-pivot Lomuto, iterative stack), Hardened
Quick Sort (median-of-three plus three-way partition), bottom-up Heap Sort, a size-K heap selector (the root is the worst retained case: a min-heap on the score with the
descending comparator reversed), a bounded insertion buffer with binary search and explicit shifting, and all three live-feed strategies. No built-in or NumPy sort appears
inside a contender; sorted() is confined to the labelled reference/verification code and to deterministic input preparation. A key comparison is one call to the central
TriageOrder.cmp; a move is one record assignment (a swap is three). Timers exclude CSV I/O, risk scoring, condition construction, input copying and verification.
Correctness and the C6 clash. The automated suite has 37 passing tests, including empty input, one record, all-equal keys, duplicate-heavy input, every condition and size,
Class perturbation, Top-K boundaries and live-feed publication. C1–C5 use a total key and are checked for exact sequence equality with the reference. C6 is defined by the
PDF as band alone, so it has huge ties; a literal C6 result is checked as a permutation with non-increasing bands and no access to Amount, Time, txn_id or Class. Exact
sequence equality is impossible there without adding an illegal secondary key. This is the disclosed specification clash; the official change request was not supplied, so no
change is invented. Conditions are C1 arrival, C2 seeded shuffle, C3 pre-ranked, C4 reverse-ranked, C5 with floor(0.01n) records deranged, C6 band-only.
